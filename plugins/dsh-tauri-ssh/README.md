# DSH SSH 管理

远端探测加载登录用户 shell 的交互初始化，必要时补读登录初始化，提取 PATH 后交给 DSH 探测及启动。Bash 的交互初始化包含 `.bashrc`。此步骤需要 Linux 的 `timeout` 和 `setsid`，每次 shell 初始化限时 10 秒、输出上限 64 KiB；杂音不进入消息协议，失败明确报告扫描失败，不据此断言软件未安装。用户 shell 初始化脚本本身可能产生副作用。别名和 shell 函数不作为安装路径；请提供 PATH 中的实际可执行文件。

随 Desktop 安装包提供的 DSH 插件。`desktop` 入口提供配置页，`SshManager` 同时作为 Cordis 服务和 Desktop 标准输入输出宿主的实现；Rust 只负责宿主进程与消息转发。

在「配置 → 应用 → DSH 连接」添加 Linux 主机或 SSH Host 别名。用户名和 SSH 端口留空时继承系统 SSH 配置。使用系统 OpenSSH、默认密钥、ssh-agent、ProxyJump 和 known_hosts，不读取或保存私钥内容。必须先在终端完成主机指纹确认、密钥解锁等交互，支持 `ssh -o BatchMode=yes` 的连接。插件不绕过主机密钥校验。

每台远端机器管理一个当前登录用户的 DSH，HTTP 仅监听 `127.0.0.1:3080`，桌面通过本地回环 SSH 隧道连接；SSH 服务必须允许本地端口转发。主机 SSH 端口之外不需要开放服务端口。多个主机可同时显示在现有工作区树。原始 SSH 地址与桌面自动分配的隧道端口分开保存；隧道端口被其他进程占用会报错，不接管该进程。

远端底层版本位于 `~/.local/share/dsh-desktop/versions`，数据位于 `~/.dsh`。与 Desktop 使用同一 `dsh-tauri-desk/deepseek-harness-pkg` 发行源，校验 GitHub 提供的 SHA-256 后由随包解压器解压。当前 Linux 发行包面向 x64；不把它当作 ARM 包使用。首次检测不写入远端文件；安装需要 GitHub 与 npm 网络访问，缺少兼容 Node/npm 时还需要 curl、tar、xz、sha256sum 和 nodejs.org 网络访问。安装不使用 sudo，不修改全局 Node/DSH。发现已有数据或全局 DSH 时必须确认接管，已有运行中的 DSH 须由用户先停止；接管前在托管目录的 backups 下保留原有数据副本。

新版 DSH 的启动令牌通过 SSH 从本插件拥有的服务日志读取并兑换浏览器凭据。凭据仅保存在本地代理内存，不写入连接配置，也不发给嵌入页面；代理使用远端的回环地址转发 HTTP 和 WebSocket，不关闭 DSH 鉴权。桌面页面的入口使用临时随机令牌，本地代理拒绝其他网页来源和非回环 Host。每次重新连接更新令牌，服务重启后的健康检查会重新认证。

「配置 → 底层」和「配置 → 插件」可选择管理目标。升级先安装目标版本，停服务后保存数据快照，再启动新版本；安装和插件操作可能执行第三方包脚本，必须信任来源。恢复旧版本须再次确认，会恢复快照中的数据并另存升级后的数据。远端锁防止两个桌面同时修改；SSH 中断后的操作结果应重新检查，不把断线视为失败回滚。

断开、删除连接或退出桌面只关闭本地 SSH 进程，不停止远端 DSH，不删除远端安装、插件或会话。仅「停止」显式终止本插件记录并核对过身份的服务进程组。远端进程脱离 SSH 会话运行；本版不配置开机自启，主机重启或系统登录会话清理策略仍可能停止它，重新连接时会启动已托管的 DSH。

先运行 `pnpm --filter dsh-tauri-ssh build`，再以 `node --test plugins/dsh-tauri-ssh/test/*.node-test.mjs` 运行插件测试。真实 SSH 验收须使用隔离 Linux 用户/数据，不指向生产主机。
