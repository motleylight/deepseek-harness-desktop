# Connections browser acceptance

Run independent DSH web profiles on ports 3181 and 3182. Install `dsh-tauri-connections` only on 3181; keep 3182 unmodified. Keep both `DSH_HOME` directories separate from production. Build the plugin, run `node test/manual/external-companion-proxy.mjs`, and start `pnpm dev --host 127.0.0.1 --port 1420`. Open `http://127.0.0.1:1420/test/manual/connections-acceptance.html`.

This harness renders the actual plugin desktop components and embeds the real DSH clients. The loopback proxy on 3183 serves 3182 with the built companion inserted before DSH scripts, simulating native document-start injection without installing a server plugin. It also renders a test-only current-session ID from the public sessions store. Restart the proxy after rebuilding. Native configuration calls use an in-memory adapter: port 3183 is accepted and other ports produce a deterministic probe failure. The test-only Application button and session ID readout are not included in production. No model request is needed; skip API-key onboarding and create a test workspace with two same-title sessions on 3182.

The settings button uses the production `AppProviders`, `useOverlay(ConfigDialog)`, and all four real settings pages. Open Application, Profiles, Plugins, and Core, then close and reopen the dialog while retaining both DSH frames. The disconnected SSH fixture tests provider availability; it does not establish an SSH connection. The native adapter is installed before importing application stores so their event listeners use the same adapter.

Check the shared tree, distinct IDs when opening same-title sessions, renaming from both entry points, invalid-address preservation, disconnect/reconnect, and absence of duplicate sidebars. Add a local workspace after the external list has loaded: the local workspace and its sessions must appear between the local header and external groups, and remain usable after collapse, selection, and refresh. Compare font size, row height, folder disclosure, hover, and session alignment against a direct visit to 3181. Browser acceptance does not cover native window behavior, native probing or installer execution; use the Rust tests and Windows build for those separate signals.
