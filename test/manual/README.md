This harness renders the actual plugin desktop components and embeds the real DSH clients. The loopback proxy on 3183 serves 3182 with the built companion inserted before DSH scripts, simulating native document-start injection without installing a server plugin. It also renders a test-only current-session ID from the public sessions store. For the current Controller-based DSH, run a third isolated profile on 3185; the proxy exposes it at 3186 and forwards its WebSocket transport. Native configuration calls use an in-memory adapter: ports 3183 and 3186 are accepted, other ports produce a deterministic probe failure. The test-only Application button and session ID readout are not included in production. No model request is needed; skip API-key onboarding and create test workspaces and sessions. Use the 127.0.0.1 parent URL for the browser acceptance harness and authenticate the 3186 origin with the isolated server's startup URL before embedding it; do not store its token in committed fixtures.

The disconnected SSH fixture tests provider availability; it does not establish an SSH connection. The native adapter is installed before importing application stores so their event listeners use the same adapter.

Check the shared tree, distinct IDs when opening same-title sessions, renaming from both entry points, invalid-address preservation, disconnect/reconnect, and absence of duplicate sidebars. Browser acceptance does not cover native window behavior, native probing or installer execution; use the Rust tests and Windows build for those separate signals.
