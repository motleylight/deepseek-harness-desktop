# Connections browser acceptance

For the native desktop toolbar and full context menus, mount the bundled `dsh-tauri`, `dsh-tauri-ui`, `dsh-tauri-panel` and `dsh-tauri-rightclick` plugins on the isolated managed profile. Also test without `dsh-tauri-rightclick` to verify the native workspace-menu fallback. The proxy exposes this profile at 3184, applying the launcher's existing SlotOutlet export patch in memory. No installed core files are changed. Port 3183 exposes the unmodified external profile with document-start companion injection. The proxy reads companion bytes on each page load; reload the browser after a build. The adapter's managed frame uses 3184.

Open an external session and use the top New session action: it must inherit that DSH's workspace without a selection dialog. Use workspace hover/context actions while another connection is selected and verify creation stays on the row's connection. Create a workspace from a connection hover/context action and verify no endpoint picker appears and the managed registry stays unchanged. Flat view must merge all connections without headers, expose both ownership badges, and retain session menus. Test each badge's scoped creation, native local workspace menus, cross-connection session clicks, retained iframe identities, and group/flat restoration. Running/unread markers have keyless transition and rendered-row tests; real runtime execution requires a configured model and is a separate acceptance signal. Search and settings must remain usable.

Run independent DSH web profiles on ports 3181 and 3182. Install `dsh-tauri-connections` only on 3181; keep 3182 unmodified. Keep both `DSH_HOME` directories separate from production. Build the plugin, run `node test/manual/external-companion-proxy.mjs`, and start `pnpm dev --host 127.0.0.1 --port 1420`. Open `http://127.0.0.1:1420/test/manual/connections-acceptance.html`.

This harness renders the actual plugin desktop components and embeds the real DSH clients. The loopback proxy on 3183 serves 3182 with the built companion inserted before DSH scripts, simulating native document-start injection without installing a server plugin. It also renders a test-only current-session ID from the public sessions store. For the current Controller-based DSH, run a third isolated profile on 3185; the proxy exposes it at 3186 and forwards its WebSocket transport. Native configuration calls use an in-memory adapter: ports 3183 and 3186 are accepted, other ports produce a deterministic probe failure. The test-only Application button and session ID readout are not included in production. No model request is needed; skip API-key onboarding and create test workspaces and sessions. Use the 127.0.0.1 parent URL for the browser acceptance harness and authenticate the 3186 origin with the isolated server's startup URL before embedding it; do not store its token in committed fixtures.

The settings button uses the production `AppProviders`, `useOverlay(ConfigDialog)`, and all four real settings pages. Open Application, Profiles, Plugins, and Core, then close and reopen the dialog while retaining both DSH frames. The disconnected SSH fixture tests provider availability; it does not establish an SSH connection. The native adapter is installed before importing application stores so their event listeners use the same adapter.

Check the shared tree, distinct IDs when opening same-title sessions, renaming from both entry points, invalid-address preservation, disconnect/reconnect, and absence of duplicate sidebars. Add a local workspace after the external list has loaded: the local workspace and its sessions must appear between the local header and external groups, and remain usable after collapse, selection, and refresh. Compare font size, row height, folder disclosure, hover, and session alignment against a direct visit to 3181. Browser acceptance does not cover native window behavior, native probing or installer execution; use the Rust tests and Windows build for those separate signals.
